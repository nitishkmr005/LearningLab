# Model Evaluation — Interview Q&A

> Covers: Confusion matrix, Precision/Recall, F1 score, ROC/AUC, accuracy pitfalls, false positive vs. false negative trade-offs, threshold selection — the metrics every DS/ML/AI engineer must know for production systems.

---

## Q1: What is a Confusion Matrix? Walk me through a worked example.

A confusion matrix is a 2×2 table (for binary classification) that breaks down a model's predictions against actual labels into four categories.

**Confusion Matrix:**

|  | Predicted Positive | Predicted Negative |
|---|---|---|
| **Actual Positive** | TP (True Positive) | FN (False Negative) |
| **Actual Negative** | FP (False Positive) | TN (True Negative) |

**Worked example — Email spam filter (100 emails, 20 actual spam):**

|  | Predicted Spam | Predicted Not Spam |
|---|---|---|
| **Actual Spam** | 15 (TP) | 5 (FN) |
| **Actual Not Spam** | 3 (FP) | 77 (TN) |

- TP = 15: Correctly flagged spam
- FN = 5: Missed spam (landed in inbox)
- FP = 3: Legitimate emails incorrectly flagged as spam
- TN = 77: Correctly allowed through

**Intuition:** Raw accuracy hides all this nuance. The confusion matrix reveals *which kinds* of errors the model makes — which is often more important than overall accuracy.

## Q2: What are Precision and Recall, and when does each matter more?

**Precision** (Positive Predictive Value): Of all the items predicted positive, how many actually are positive?

$$\text{Precision} = \frac{TP}{TP + FP}$$

**Recall** (Sensitivity / True Positive Rate): Of all the items that actually are positive, how many did the model catch?

$$\text{Recall} = \frac{TP}{TP + FN}$$

**When Precision matters more (FP cost is high):**
- **Spam filter:** A false positive sends a legitimate email to spam — user misses important messages. Low precision is very disruptive.
- **Stock market alert:** Alerting a trader to buy when the signal is wrong costs real money.
- **Legal discovery:** Flagging innocent documents wastes expensive lawyer time.

**When Recall matters more (FN cost is high):**
- **Cancer screening:** A false negative means a patient with cancer is told they're healthy — potentially fatal.
- **Fraud detection:** Letting fraudulent transactions through costs money.
- **Structural defect detection:** Missing a defective aircraft part is catastrophic.

**Intuition:** Precision says "don't cry wolf." Recall says "don't miss any wolves."

**From the spam example above:**
- Precision = 15/(15+3) = 0.833
- Recall = 15/(15+5) = 0.75

## Q3: What is the F1 Score and when do you use it over accuracy?

F1 score is the **harmonic mean** of Precision and Recall:

$$F1 = 2 \cdot \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{2 \cdot TP}{2 \cdot TP + FP + FN}$$

**Why harmonic mean?** Unlike arithmetic mean, the harmonic mean is low if either Precision or Recall is low — it punishes imbalance between the two. A model with Precision=1.0 and Recall=0.01 would have arithmetic mean = 0.505 but F1 = 0.02 (correctly low).

**When to use F1 over accuracy:**
- Imbalanced datasets where one class dominates (accuracy is misleading)
- When you care about both FP and FN errors (not just one)
- Binary classification where positive class is the minority (fraud, disease, defects)

**F1 variants:**
- **F-beta:** $F_\beta = (1+\beta^2) \cdot \frac{\text{Precision} \times \text{Recall}}{\beta^2 \cdot \text{Precision} + \text{Recall}}$ — β > 1 weights recall more, β < 1 weights precision more.

**Example:** For fraud detection (1% fraud rate), a model that predicts "no fraud" always gets 99% accuracy but F1 = 0. F1 correctly reveals this model is useless.

## Q4: What are True Positive Rate and False Positive Rate, and how do they relate to the ROC curve?

**True Positive Rate (TPR = Recall = Sensitivity):**
$$TPR = \frac{TP}{TP + FN}$$
The fraction of actual positives that are correctly identified.

**False Positive Rate (FPR = Fall-out):**
$$FPR = \frac{FP}{FP + TN}$$
The fraction of actual negatives that are incorrectly classified as positive.

**ROC Curve:** A plot of **TPR (y-axis) vs. FPR (x-axis)** at every possible classification threshold from 0 to 1.

- At threshold = 1.0: Model predicts everything negative → TPR = 0, FPR = 0 (bottom-left)
- At threshold = 0.0: Model predicts everything positive → TPR = 1, FPR = 1 (top-right)
- Moving the threshold trades off TPR for FPR

**Intuition:** The ROC curve shows the full range of trade-offs available. A model that hugs the top-left corner is ideal (high TPR at low FPR across all thresholds).

**Example:** Fraud detection model at threshold 0.5: TPR = 0.80, FPR = 0.10. Lowering to threshold 0.3 increases TPR to 0.90 but also raises FPR to 0.25.

## Q5: What is AUC (Area Under the ROC Curve), and how do you interpret it?

**AUC** is the area under the ROC curve — a single number summarizing the model's discrimination ability across all thresholds.

**Interpretation:**

| AUC | Meaning |
|---|---|
| 1.0 | Perfect classifier — separates all positives from negatives |
| 0.9–1.0 | Excellent |
| 0.8–0.9 | Good |
| 0.7–0.8 | Fair |
| 0.5 | Random classifier (diagonal line) |
| < 0.5 | Worse than random (predictions are inverted) |

**Probabilistic interpretation:** AUC = probability that the model ranks a random positive example higher than a random negative example.

**Intuition:** AUC is threshold-agnostic. It tells you how well the model *separates* the two classes at any threshold, not just at 0.5.

**Example:** A cancer detection model with AUC = 0.95 means: if you pick one cancer patient and one healthy patient at random, the model will rank the cancer patient higher 95% of the time.

## Q6: How do you choose the right classification threshold?

The default threshold of 0.5 is often not optimal. Threshold selection depends on the cost of each error type.

**Methods for choosing threshold:**

1. **ROC curve + Youden's Index:** Maximize TPR − FPR (point on ROC curve farthest from the diagonal)
   $$J = \text{TPR} - \text{FPR}$$

2. **Precision-Recall curve:** For highly imbalanced datasets, plot Precision vs. Recall at each threshold. Choose the threshold at the "elbow" or where F1 is maximized.

3. **Business cost matrix:** Assign dollar costs to FP and FN, then choose the threshold that minimizes total expected cost.
   $$\text{Cost} = C_{FP} \cdot FP + C_{FN} \cdot FN$$

4. **Domain constraint:** In healthcare, you might require Recall ≥ 0.99 (cannot miss disease), then maximize precision given this constraint.

**Intuition:** There's no universal best threshold — it's a business decision that quantifies the cost ratio of FP vs. FN errors.

**Example:** Cancer screening with asymmetric costs (FN = surgery missed = very costly): lower threshold to 0.3, accepting more FP (unnecessary follow-up scans) to catch nearly all cancers.

## Q7: Why is accuracy a misleading metric for imbalanced datasets?

**Problem:** In an imbalanced dataset where 99% of samples are negative (class 0) and 1% are positive (class 1), a model that predicts "always negative" achieves **99% accuracy** — yet it is completely useless.

**Accuracy formula:**
$$\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}$$

When one class dominates, TN dominates the numerator, inflating accuracy.

**Better alternatives for imbalanced data:**

| Metric | Why Better |
|---|---|
| Precision / Recall | Focus only on positive class performance |
| F1 Score | Balanced measure of precision and recall |
| AUC-ROC | Threshold-agnostic, rank-based measure |
| Matthews Correlation Coefficient (MCC) | Balanced even with extreme class imbalance |
| AUC-PR (Precision-Recall AUC) | More informative than ROC for highly skewed data |

**Intuition:** Accuracy answers "how often are you right overall?" But with 1% positives, "always wrong about the positive class" still gives 99% accuracy.

**Example:** Credit card fraud (0.1% fraud rate): a naive model gets 99.9% accuracy by predicting "no fraud" always. Recall = 0%, making it worthless for the actual task.

## Q8: What is the false positive vs. false negative trade-off? Give examples where each is more costly.

**FP (False Positive / Type I Error):** Predicted positive, actually negative. "Cried wolf."
**FN (False Negative / Type II Error):** Predicted negative, actually positive. "Missed the wolf."

**Cases where FP cost > FN cost (minimize FP → increase Precision):**

| Domain | FP | Cost of FP |
|---|---|---|
| Spam filter | Ham flagged as spam | User misses important email |
| Stock trading signal | False buy alert | Money lost on bad trade |
| Legal document review | Irrelevant doc flagged | Lawyer time wasted |
| Recommendation | Irrelevant recommendation | User annoyance |

**Cases where FN cost > FP cost (minimize FN → increase Recall):**

| Domain | FN | Cost of FN |
|---|---|---|
| Cancer screening | Cancer patient told "healthy" | Disease progresses, potentially fatal |
| Fraud detection | Fraudulent transaction cleared | Financial loss |
| Structural defect detection | Defective part ships | Catastrophic failure |
| Terrorist screening | Threat missed | Public safety risk |

**Intuition:** In life-safety applications, FN is almost always more costly. In user-experience applications (spam, recommendations), FP may be more costly because it damages trust.

**Example trade-off:** A COVID test with 95% recall and 70% precision vs. 85% recall and 95% precision — for public health screening, prefer the first (catch more cases, accept more false alarms). For confirming before treatment, prefer the second (don't treat healthy people).

## Q9: What is Specificity, and how does it differ from Precision?

**Specificity (True Negative Rate):**
$$\text{Specificity} = \frac{TN}{TN + FP}$$

Measures how well the model identifies **actual negatives**.

**Specificity vs. Precision:**
- **Specificity** asks: "Of all actual negatives, how many did we correctly label negative?"
- **Precision** asks: "Of all predicted positives, how many actually are positive?"

Both are ways to measure false positive behavior, but from different denominators:
- Specificity denominator = total actual negatives (TN + FP)
- Precision denominator = total predicted positives (TP + FP)

**Intuition:** In medical testing — Sensitivity (Recall) = "catch all sick people." Specificity = "don't falsely alarm healthy people." FPR = 1 − Specificity.

**Example:** A COVID test with Specificity = 0.98 means: of 100 healthy people tested, 98 are correctly told they're healthy; 2 get a false positive result.

## Q10: When would you use AUC-PR (Precision-Recall AUC) instead of AUC-ROC?

**AUC-ROC** can be overly optimistic when the negative class heavily dominates. Because FPR uses TN in the denominator — and with millions of TN (e.g., fraud: 99.9% non-fraud) — even a model with many FPs can show a small FPR, making the ROC curve look great.

**AUC-PR** focuses entirely on the positive class (TP, FP, FN) and is much more informative when:
- The positive class is rare (< 5% of data)
- You care much more about detecting positives than avoiding false alarms on negatives

**Rule of thumb:**
- Balanced classes or care about both classes equally → AUC-ROC
- Highly imbalanced, rare positive class → AUC-PR

**Example:** Fraud detection at 0.1% fraud rate: A model might show AUC-ROC = 0.98 (looks great!) but AUC-PR = 0.35 (actually struggles to find the rare fraud cases). AUC-PR tells the honest story.

## Q11: What is the difference between micro, macro, and weighted averaging for multiclass metrics?

For K-class classification problems, Precision/Recall/F1 can be averaged in three ways:

**Macro average:** Compute metric for each class independently, then take the unweighted mean. Treats all classes equally regardless of size.
$$\text{Macro-F1} = \frac{1}{K}\sum_{k=1}^{K} F1_k$$

**Micro average:** Aggregate TP, FP, FN across all classes, then compute metric once. Equivalent to accuracy for balanced datasets. Favors large classes.
$$\text{Micro-F1} = \frac{2 \sum TP_k}{2 \sum TP_k + \sum FP_k + \sum FN_k}$$

**Weighted average:** Compute metric for each class, then take a weighted mean using class support (number of samples per class).

**When to use which:**
- **Macro:** When small classes matter equally (e.g., rare disease detection — don't let the common class dominate)
- **Micro:** When overall instance-level performance matters more (large datasets, balanced enough)
- **Weighted:** Best for reporting on imbalanced datasets where class frequency should influence the metric

**Example:** If class A has 10,000 samples and class B has 100 samples, Macro-F1 treats them equally. Micro-F1 will mostly reflect model performance on class A. Weighted-F1 lies in between, proportionally.
