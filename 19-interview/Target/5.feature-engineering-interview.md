## Q1: What is feature scaling, and when is it required vs. not required?

Feature scaling normalizes the magnitude of features so that no single feature dominates due to its units or range. There are two main approaches: standardization and normalization.

**When feature scaling IS required:**
- **Distance-based algorithms:** KNN, K-Means (Euclidean distance is unit-sensitive)
- **SVM:** Margin depends on distances between points
- **Neural Networks / Gradient Descent:** Faster convergence when features are on similar scales (avoids elongated loss surfaces)
- **PCA:** Variance-based; large-magnitude features dominate principal components
- **Linear/Logistic Regression:** Gradient descent converges faster with scaled features

**When feature scaling is NOT required:**
- **Tree-based models:** Decision Trees, Random Forest, XGBoost — splits are threshold comparisons, not distance-based. Scale is irrelevant.
- **Naive Bayes:** Works on probabilities, not distances.

**Intuition:** If the algorithm computes distances or gradients, scale matters. If it splits on thresholds, scale is irrelevant.

**Example:** KNN on a dataset with "age" (25–65) and "income" (20,000–200,000). Without scaling, income dominates all distances; a 1-unit age difference becomes meaningless.

## Q2: What is the difference between Standardization and Min-Max Normalization?

**Standardization (Z-score scaling / StandardScaler):**
$$x' = \frac{x - \mu}{\sigma}$$
Output: μ = 0, σ = 1. No fixed range — values can extend beyond [0,1].

**Min-Max Normalization (MinMaxScaler):**
$$x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}$$
Output: All values in [0, 1].

**Mean Normalization:**
$$x' = \frac{x - \mu}{x_{\max} - x_{\min}}$$
Output: Centered at 0, roughly in [−1, 1].

**When to use each:**

| Situation | Recommendation |
|---|---|
| Algorithm assumes normality (e.g., linear models) | Standardization |
| Fixed-range required (e.g., image pixel values 0–1) | Min-Max |
| Outliers present | Standardization (more robust than min-max) |
| Neural networks | Either works; standardization slightly preferred |

**Intuition:** Standardization is more robust — one outlier in min-max scaling compresses all other values into a tiny range. Standardization spreads the outlier's effect across z-scores.

**Example:** Image pixel values (0–255): min-max scales to [0, 1]. Sensor readings with occasional extreme spikes: standardization handles outliers better.

**Step-by-step numerical walkthrough — data with an outlier:**

Dataset: `[10, 20, 30, 40, 100]` (the value 100 is an outlier; the rest are evenly spaced).

**Standardization (Z-score scaling):**

**Step 1 — Compute mean:**
$$\mu = \frac{10 + 20 + 30 + 40 + 100}{5} = \frac{200}{5} = \mathbf{40.0}$$

**Step 2 — Compute standard deviation:**

Squared deviations from 40: (10−40)² = 900, (20−40)² = 400, (30−40)² = 100, (40−40)² = 0, (100−40)² = 3600

$$\sigma = \sqrt{\frac{900 + 400 + 100 + 0 + 3600}{5}} = \sqrt{\frac{5000}{5}} = \sqrt{1000} \approx 31.62$$

**Step 3 — Compute z-scores** (x − 40) / 31.62:

| x | z-score |
|---|---|
| 10 | (10−40)/31.62 = **−0.95** |
| 20 | (20−40)/31.62 = **−0.63** |
| 30 | (30−40)/31.62 = **−0.32** |
| 40 | (40−40)/31.62 = **+0.00** |
| 100 | (100−40)/31.62 = **+1.90** |

The four "normal" values spread from −0.95 to 0.00 — still distinguishable from each other.

**Min-Max Normalization:**

x_min = 10, x_max = 100 → range = 90.

**Step 1 — Apply formula** (x − 10) / 90:

| x | scaled value |
|---|---|
| 10 | (10−10)/90 = **0.000** |
| 20 | (20−10)/90 = **0.111** |
| 30 | (30−10)/90 = **0.222** |
| 40 | (40−10)/90 = **0.333** |
| 100 | (100−10)/90 = **1.000** |

The outlier 100 is anchored at 1.0, but the four non-outlier values [10, 20, 30, 40] are compressed into the narrow band [0.000, 0.111, 0.222, 0.333]. A KNN model using min-max features would still see these four points as far closer to each other than to the outlier, but the absolute spread is only 0.333 vs. 1.90 in standardization. **If a second outlier appeared during inference below 10 or above 100, min-max would produce values outside [0,1] entirely**, breaking models like neural networks that expect bounded inputs.

**Key production lesson:** With min-max, one extreme value at train time compresses everything else. This is especially dangerous in streaming/online systems where the distribution may shift after deployment. Standardization is more robust because new outliers only shift z-scores modestly.

## Q3: What techniques exist for handling missing data?

**Deletion methods:**
- **Listwise deletion (complete case analysis):** Remove any row with at least one missing value. Simple, but loses data — only acceptable if missingness is completely random (MCAR) and < 5% of rows are affected.
- **Pairwise deletion:** Use all available data for each specific computation. Inconsistent sample sizes across analyses.

**Imputation methods:**

| Method | When to Use |
|---|---|
| **Mean imputation** | Continuous features, data is normally distributed, few missing values |
| **Median imputation** | Continuous features with outliers or skewed distribution |
| **Mode imputation** | Categorical features |
| **KNN imputation** | When similar records have similar missing values; computationally expensive |
| **Multiple Imputation (MICE)** | When data is Missing At Random (MAR); creates multiple imputed datasets |
| **Model-based** (Random Forest imputer) | Complex missingness patterns, non-linear relationships |

**Add a missingness indicator:** For non-trivial missingness, add a binary column `feature_was_missing` — the fact that a value was missing may itself be informative.

**Intuition:** Never just delete. Missing data rarely occurs completely at random. Understand *why* values are missing before deciding how to handle them.

**Example:** In a medical dataset, missing lab values may indicate the test was not ordered (patient not at risk) — the missingness itself is informative and should be captured as a feature.

## Q4: What is the Curse of Dimensionality?

The curse of dimensionality refers to the phenomenon where adding more features (dimensions) initially improves model performance, but beyond a threshold, performance degrades as dimensionality grows.

**Why it happens:**
1. As dimensions increase, the volume of the feature space grows **exponentially** — data becomes extremely sparse
2. With sparse data, distance metrics become meaningless (all points are roughly equidistant from each other in high dimensions)
3. The model gets confused by too many features, many of which may be noisy or irrelevant
4. Training data requirements grow exponentially with dimensions to maintain the same data density

**The pattern:**
- Add 2 features → accuracy improves
- Add 5 features → still improving
- Add 100 features → accuracy peaks then degrades
- Add 10,000 features → accuracy much worse than with 10 features

**Intuition:** Think of trying to find a friend in a 2D city block — easy. Now find them in a 3D building — harder. Now in a million-dimensional space — impossible. More dimensions paradoxically make the problem harder.

**Solutions:**
- **Feature selection** — keep only the most informative features
- **PCA** — project to fewer orthogonal dimensions that capture most variance
- **Regularization** (L1/L2) — penalizes complexity, effectively reduces effective dimensions

**Example:** A TF-IDF matrix for 10,000 unique words creates 10,000 features. For KNN, all documents become equidistant in this space. PCA might reduce this to 50–100 meaningful dimensions while preserving 90%+ of variance.

## Q5: What is Cross-Validation, and why is it better than a single train/test split?

Cross-validation evaluates model performance by training and testing on different subsets of the data multiple times, then averaging the results.

**Problem with single train/test split:** The accuracy depends heavily on which random 30% ended up in the test set. A different random split can give 78% or 91% — the result is unstable.

**K-Fold Cross-Validation:**
1. Divide data into K equal folds (e.g., K=5, each fold = 20% of data)
2. In iteration i: Use fold i as the test set, remaining K−1 folds as training
3. Repeat for all K folds, get K accuracy scores
4. Final score = mean (and std) of K scores

**Variants:**

| Type | Description | When to Use |
|---|---|---|
| **K-Fold** | Basic version | Balanced class distribution |
| **Stratified K-Fold** | Preserves class proportions in each fold | Imbalanced datasets |
| **Leave-One-Out (LOO)** | K = n (each sample is its own test fold) | Very small datasets |
| **Time-Series Split** | Respects temporal order — only train on past | Time-series data |

**Additional use:** Cross-validation is used for **model selection** — run CV for multiple algorithms (logistic regression, decision tree, random forest) and pick the one with the best average CV score.

**How to choose K:**
- K=5 or K=10 is the standard. K=10 gives slightly more reliable estimates at higher compute cost.
- Small datasets: Use LOO or K=5 to maximize training data.

**Intuition:** Cross-validation is an efficient way to use all your data for both training and validation — every sample participates in testing exactly once.

**Example:** 500 samples, K=5. Fold sizes = 100. Train on 400, test on 100 — repeated 5 times with different test folds. Final accuracy = mean of 5 accuracy values ≈ true generalization accuracy.

## Q6: What is Feature Selection and what are the three families of methods?

Feature selection identifies the most relevant subset of features to improve model performance, reduce overfitting, and speed up training.

**1. Filter Methods** (model-independent, fast):
- **Pearson Correlation:** Remove features highly correlated with each other (multicollinearity); keep features correlated with target
- **Chi-Square Test:** For categorical features vs. categorical target — measures statistical dependence
- **Mutual Information:** Measures general (non-linear) dependence between feature and target
- **Variance Threshold:** Remove features with near-zero variance (they carry no information)

**2. Wrapper Methods** (use the model itself, slower but more accurate):
- **Recursive Feature Elimination (RFE):** Train model, rank features by importance, remove weakest, repeat until desired number of features remains
- **Forward Selection:** Start with no features, greedily add the feature that improves CV score most, until no improvement
- **Backward Elimination:** Start with all features, greedily remove the feature whose removal hurts CV score least

**3. Embedded Methods** (feature selection is part of training):
- **L1 Regularization (Lasso):** Drives irrelevant feature coefficients exactly to zero — automatic feature selection
- **Tree Feature Importance:** Random Forest and XGBoost compute feature importances from split gain; low-importance features can be dropped

**Intuition:** Filters are fast but ignore feature interactions. Wrappers find the best subset but are expensive. Embedded methods are the sweet spot — they select features while training the final model.

**Example:** Starting with 100 features in a Lasso regression with CV-tuned α: the model might reduce effective features to 15, automatically dropping 85 irrelevant or redundant predictors.

## Q7: What is Multicollinearity, how do you detect it, and how do you fix it?

Multicollinearity is when two or more independent features are highly correlated with each other (e.g., r > 0.9). It makes individual coefficient estimates unstable — small changes in data produce large swings in fitted coefficients — though predictions remain stable.

**Detection:**
1. **Correlation heatmap:** Plot pairwise correlations; flag any pair with |r| > 0.8–0.9
2. **Variance Inflation Factor (VIF):** For each feature, VIF = 1/(1 − R²_j) where R²_j is from regressing feature j on all other features
   - VIF = 1: No multicollinearity
   - VIF 1–5: Moderate (acceptable)
   - VIF > 5–10: High multicollinearity — take action

**Solutions:**
1. **Drop one feature** from each highly correlated pair — the simplest fix
2. **Ridge Regression (L2):** Adds λ||w||² penalty, which shrinks correlated coefficients toward each other and stabilizes estimates
3. **Lasso (L1):** Drives one of the correlated features to exactly zero
4. **PCA:** Replace correlated features with orthogonal principal components that are by definition uncorrelated

**Intuition:** Correlated features tell the model the same information twice. The model can't determine how to split the credit — leading to wild coefficient swings but stable predictions.

**Example:** Predicting house price with both "total sqft" and "number of rooms" — these are 90% correlated. The coefficient for sqft might be +1000 in one dataset split and −500 in another. Dropping "number of rooms" stabilizes the model.

## Q8: How do you handle imbalanced datasets?

An imbalanced dataset has a highly skewed class distribution (e.g., 99% class 0, 1% class 1). Standard models will be biased toward predicting the majority class.

**Resampling techniques:**

**Undersampling (reduce majority class):**
- Randomly remove samples from majority class to match minority class size
- Pro: Faster training. Con: Throws away potentially useful data.
- Library: `imblearn.under_sampling.NearMiss`, `RandomUnderSampler`

**Oversampling (increase minority class):**
- **Random oversampling:** Duplicate minority class samples (simple, risk of overfitting exact duplicates)
- **SMOTE (Synthetic Minority Over-sampling Technique):** Create *synthetic* minority samples by interpolating between existing minority samples in feature space
- Pro: No information loss from undersampling. Con: May introduce noise if minority class is noisy.
- Library: `imblearn.over_sampling.SMOTE`

**Combined: SMOTE + Tomek Links:** SMOTE to oversample + Tomek Links to clean ambiguous boundary samples → often best of both worlds.

**Algorithm-level approaches:**
- **Class weights:** Tell the model to penalize misclassifications of the minority class more heavily. In scikit-learn: `class_weight='balanced'` — automatically sets weights inversely proportional to class frequencies.
- **Threshold adjustment:** Lower the classification threshold from 0.5 to 0.3 to flag more positives (increases recall at cost of precision).

**Choosing the right evaluation metric:**
- Never use accuracy for imbalanced data
- Use F1, AUC-ROC, AUC-PR, or Matthews Correlation Coefficient (MCC)

**Example:** Credit card fraud (0.1% fraud): SMOTE increases fraud samples from 500 to 50,000 synthetically. Class weight = 1000x for fraud class. Then evaluate using AUC-PR since fraud is extremely rare.

## Q9: What is Cosine Similarity, and when is it better than Euclidean distance?

**Cosine Similarity** measures the angle between two vectors, not the distance between their endpoints:

$$\cos(\theta) = \frac{A \cdot B}{\|A\| \cdot \|B\|} = \frac{\sum_{i=1}^{n} A_i B_i}{\sqrt{\sum A_i^2} \cdot \sqrt{\sum B_i^2}}$$

**Range:** −1 to +1
- cos θ = 1: Vectors point in the same direction (identical content)
- cos θ = 0: Vectors are orthogonal (no similarity)
- cos θ = −1: Vectors point in opposite directions

**Cosine Distance:**
$$\text{Cosine Distance} = 1 - \cos(\theta)$$

**Euclidean Distance** measures the straight-line distance between two points:
$$d = \sqrt{\sum_{i=1}^{n} (A_i - B_i)^2}$$

**When Cosine Similarity is better:**

| Scenario | Why Cosine Wins |
|---|---|
| **NLP / Text similarity** | A short document about "cats" and a long document about "cats" are semantically similar — Euclidean would call them far apart due to length |
| **High-dimensional sparse vectors** | TF-IDF vectors have 10,000+ dimensions; most are 0. Magnitude differences dominate Euclidean; cosine normalizes them away |
| **Recommendation systems** | User preference vectors — a user who rated 10 movies and gave 5-star ratings is similar to one who rated 2 movies with 5 stars. Cosine captures orientation, not scale |

**When Euclidean is better:**
- Dense, low-dimensional data where magnitude matters
- K-Means clustering (after standardization)
- Spatial data (actual physical distances)

**Intuition:** Cosine similarity asks "are you pointing in the same direction?" Euclidean distance asks "how far apart are you?" For text, direction (topic) matters more than magnitude (document length).

**Example (movie recommendation):**
- Avengers: [action=1, comedy=0]
- Minions: [action=0, comedy=1]
- cos θ = (1×0 + 0×1)/(1 × 1) = 0 → Not similar

- Avengers: [action=1, comedy=0]
- Iron Man: [action=1, comedy=0]
- cos θ = 1 → Identical profile → High similarity → Recommend Iron Man to Avengers fans

**Step-by-step numerical walkthrough — TF-IDF document vectors:**

Two text documents represented as TF-IDF feature vectors over vocabulary [cat, dog, bird, fish]:
- **Doc A** = [3, 1, 0, 2]
- **Doc B** = [6, 2, 0, 4]

Doc B is simply twice the magnitude of Doc A (same proportions, different document length).

**Step 1 — Compute the dot product A · B:**
$$A \cdot B = (3 \times 6) + (1 \times 2) + (0 \times 0) + (2 \times 4) = 18 + 2 + 0 + 8 = \mathbf{28}$$

**Step 2 — Compute ||A|| (magnitude of Doc A):**
$$\|A\| = \sqrt{3^2 + 1^2 + 0^2 + 2^2} = \sqrt{9 + 1 + 0 + 4} = \sqrt{14} \approx \mathbf{3.742}$$

**Step 3 — Compute ||B|| (magnitude of Doc B):**
$$\|B\| = \sqrt{6^2 + 2^2 + 0^2 + 4^2} = \sqrt{36 + 4 + 0 + 16} = \sqrt{56} \approx \mathbf{7.483}$$

**Step 4 — Divide to get cosine similarity:**
$$\cos(\theta) = \frac{A \cdot B}{\|A\| \cdot \|B\|} = \frac{28}{3.742 \times 7.483} = \frac{28}{28.0} = \mathbf{1.00}$$

cosine = **1.0** — the two documents are pointing in exactly the same direction in vector space, meaning they have identical topical content despite one being twice as long. The model correctly identifies them as equivalent documents about the same topic.

**Contrast with Euclidean distance:**
$$d = \sqrt{(3-6)^2 + (1-2)^2 + (0-0)^2 + (2-4)^2} = \sqrt{9 + 1 + 0 + 4} = \sqrt{14} \approx \mathbf{3.74}$$

Euclidean distance = 3.74 — a significant non-zero distance, suggesting the documents are "different." A KNN retrieval model using Euclidean distance would rank Doc B as less similar to short documents about the same topic purely because of length, not content. This is exactly why **cosine similarity is the standard for text similarity, recommendation, and semantic search** — it normalizes away length/magnitude and focuses on direction (topic).

**Production note:** Embedding models (sentence-transformers, OpenAI embeddings, etc.) output L2-normalized vectors by default, making cosine similarity equivalent to the dot product — which is why vector databases like Faiss and Qdrant support inner-product search as a fast cosine approximation.

## Q10: What is the relationship between L1, L2 norms and distance metrics?

**Minkowski distance** is a generalized distance metric:
$$d(A, B) = \left(\sum_{i=1}^{n} |A_i - B_i|^p\right)^{1/p}$$

- **p = 1 (L1 norm) = Manhattan Distance:** Sum of absolute differences. Robust to outliers.
- **p = 2 (L2 norm) = Euclidean Distance:** Square root of sum of squared differences. Most common.

**Connection to regularization:**
- **L1 regularization (Lasso):** Adds $\lambda \sum |w_i|$ penalty → promotes sparsity (drives coefficients to exactly 0) → automatic feature selection
- **L2 regularization (Ridge):** Adds $\lambda \sum w_i^2$ penalty → shrinks all coefficients toward 0 (none exactly 0) → handles multicollinearity

**Intuition:** L1 penalty is a diamond-shaped constraint in weight space — its corners are on the axes, so solutions tend to land at corners where one weight is zero. L2 penalty is a sphere — solutions land anywhere on the sphere, typically with all weights small but non-zero.

**Example:** Lasso on a dataset with 100 features might produce a model with only 15 non-zero coefficients — effectively selecting 15 features. Ridge keeps all 100 but shrinks them all toward zero.

## Q11: What is Voting Classifier (Hard vs. Soft voting)?

Voting classifiers combine multiple models and aggregate their predictions — a form of ensemble learning.

**Hard Voting:** Each model outputs a class label. The final prediction is the **majority vote** (the class predicted by the most models).

**Soft Voting:** Each model outputs a probability per class. The final prediction is based on the **average probability** across models. The class with the highest average probability wins.

$$\hat{y}_{soft} = \arg\max_k \frac{1}{M} \sum_{m=1}^{M} P_m(y=k \mid x)$$

**Soft vs. Hard:**
- Soft voting is generally better when models are well-calibrated (their probability estimates are trustworthy)
- Soft voting uses more information (probability magnitudes, not just class labels)
- Hard voting is simpler and works well when individual model probabilities are unreliable

**Intuition:** In hard voting, a very confident model counts the same as an uncertain one. In soft voting, a model that says 99% probability has more influence than one that says 51%.

**Example:** 4 decision trees in Random Forest predicting fraud:
- Hard: Trees vote [1, 1, 0, 1] → majority = 1 (fraud)
- Soft: Probabilities [0.9, 0.8, 0.2, 0.7] → mean = 0.65 > 0.5 → fraud (same result but more nuanced)

## Q12: How do you handle high-cardinality categorical features?

**The problem:** A feature like `city` with 10,000 unique values cannot be one-hot encoded — that creates 10,000 binary columns, most of which are near-zero and cause the curse of dimensionality. Standard approaches break down at high cardinality.

**Approach 1 — Frequency Encoding:**

Replace each category with how often it appears in the training set.

$$x'_i = \frac{\text{count}(c_i)}{n}$$

| city | count | frequency encoded |
|---|---|---|
| New York | 5,000 | 0.50 |
| London | 3,000 | 0.30 |
| Oslo | 20 | 0.002 |

**Pros:** Simple, no data leakage, handles unseen categories (assign frequency 0). **Cons:** Two cities with the same frequency get the same encoding even if their relationship to the target is different.

---

**Approach 2 — Target Encoding (Mean Encoding):**

Replace each category with the mean of the target variable for samples in that category.

$$x'_i = \frac{\sum_{j: c_j = c_i} y_j}{\text{count}(c_i)}$$

**Step-by-step example — predicting loan default by city:**

| city | total samples | defaults | target mean |
|---|---|---|---|
| New York | 1,000 | 80 | 0.080 |
| London | 500 | 60 | 0.120 |
| Oslo | 5 | 4 | **0.800** ← unreliable |

**The key danger — target leakage and overfitting:**

Oslo has only 5 samples, 4 of which defaulted. But this is likely noise — Oslo's true default rate might be 12% like London. With only 5 samples the estimate is unreliable and will overfit: the model sees Oslo → 0.80 and memorises it.

**Fix — smoothed target encoding (production standard):**

$$x'_i = \frac{n_i \cdot \bar{y}_i + k \cdot \bar{y}_\text{global}}{n_i + k}$$

where $n_i$ is the count for category $i$, $\bar{y}_i$ is its mean target, $\bar{y}_\text{global}$ is the global mean target, and $k$ is a smoothing factor (typically 10–50).

**Worked example** with $k = 20$, global default rate = 0.10:

- New York (n=1000): $\frac{1000 \times 0.08 + 20 \times 0.10}{1000 + 20} = \frac{80 + 2}{1020} = \frac{82}{1020} \approx \mathbf{0.0804}$ — barely changed (large sample, reliable)
- Oslo (n=5): $\frac{5 \times 0.80 + 20 \times 0.10}{5 + 20} = \frac{4 + 2}{25} = \frac{6}{25} = \mathbf{0.24}$ — pulled strongly toward the global mean (small sample, unreliable)

Smoothing prevents rare categories from receiving extreme encoded values.

**Critical implementation rule — always use cross-fold target encoding:**

If you compute city's target mean on the same rows the model trains on, you leak the label into the feature → data leakage → inflated training performance. The fix:
1. Split training data into K folds
2. For each fold, compute target encoding using only the other K−1 folds
3. Apply the encoding to the held-out fold
4. For the test set, use the global encoding computed from all training data

In scikit-learn: `category_encoders.TargetEncoder` with `cv=5` handles this automatically.

---

**Approach 3 — Embedding Encoding (for neural networks):**

Learn a dense vector representation of each category during training (like word embeddings for text).

- Each category gets an embedding of dimension $d$ (typically $d = \min(50, \sqrt{\text{cardinality}}/2)$)
- The embeddings are learned end-to-end during model training
- The model learns that New York and London should have similar embeddings if they behave similarly

**Best for:** Neural networks, when categories have rich latent structure (e.g., stores in a retail chain, users in a recommendation system).

---

**Comparison table:**

| Method | Handles unseen | Risk of leakage | Works with trees | Works with NNs | Best for |
|---|---|---|---|---|---|
| One-hot | Only if column added | None | Yes (but large) | Yes | Low cardinality (< 50) |
| Frequency | Yes (freq = 0) | None | Yes | Yes | Medium cardinality, baseline |
| Target encoding | Yes (global mean) | High if not cross-fold | Yes | Yes | High cardinality, strong signal |
| Smoothed target | Yes (global mean) | Low if cross-fold | Yes | Yes | Production default for high cardinality |
| Embedding | No (OOV token) | None | No | Yes | Very high cardinality + NNs |

**Production default:** Smoothed cross-fold target encoding for tree models. Embeddings for neural networks. Always validate using a holdout that was never touched during encoding.
